# SPEC — Map Markers (SeeTree test task)

Single-page app on Mapbox GL JS + Python (FastAPI) server. No database: the server
keeps markers in memory and is the source of truth; the client re-fetches on load.

## Marker

```json
{ "id": "3f1c…", "lng": 34.78, "lat": 32.07, "score": 3 }
```

| field | type   | rule                                  |
|-------|--------|---------------------------------------|
| id    | string | uuid4, generated by the server        |
| lng   | float  | -180 ≤ lng ≤ 180                      |
| lat   | float  | -90 ≤ lat ≤ 90                        |
| score | int    | 0 ≤ score ≤ 5                         |

Color by score: `0 black (#000000)`, `1 gray (#808080)`, `2 red (#ff0000)`,
`3 orange (#ffa500)`, `4 lime (#00ff00)`, `5 green (#008000)`.

## API

All bodies are JSON. Validation errors → `422` (FastAPI default). Unknown id → `404 {"detail": "Marker not found"}`.

| method | path              | body                              | success                  | notes |
|--------|-------------------|-----------------------------------|--------------------------|-------|
| GET    | /markers          | —                                 | `200 {"markers": [...]}` | used on page load |
| GET    | /markers/export   | —                                 | `200`, same body, `Content-Disposition: attachment; filename="markers.json"` | the Export link points here |
| POST   | /markers          | `{lng, lat, score}`               | `201 Marker`             | **may randomly fail** → `503 {"detail": "Server refused to create marker"}` |
| PUT    | /markers/{id}     | `{lng, lat, score}`               | `200 Marker`             | full replace; used for score change and move |
| DELETE | /markers/{id}     | —                                 | `204`                    | |
| POST   | /markers/import   | `{"markers": [{lng, lat, score}]}`| `201 {"markers": [...]}` | appends to existing, new ids; atomic: any invalid item → `422`, nothing added; no random failure |
| DELETE | /markers          | —                                 | `204`                    | remove all |

### Failure injection

Only `POST /markers` can randomly fail. Probability 1/3 per request. The decision
lives in one function `should_fail() -> bool` in its own module so tests can
monkeypatch it to `True`/`False`. Other endpoints fail only for real reasons (404, 422).

## Client behaviour

- **Create:** click on map → popup at the click point with six buttons `0..5` →
  click a score → `POST /markers`. The marker is drawn only after `201`.
  Clicking elsewhere / Esc closes the popup without creating anything.
- **Change score:** click a marker → popup with six score buttons + `Remove` →
  `PUT /markers/{id}` → recolor on `200`.
- **Move:** markers are draggable; on `dragend` → `PUT /markers/{id}`. If the
  request fails, the marker snaps back to its previous position.
- **Remove:** `Remove` button in the marker popup → `DELETE /markers/{id}` →
  marker removed from the map on `204`.
- **Stats panel** (top-right): `Total` and count per score `Five..Zero`,
  recomputed from client state after every successful operation.
- **Errors:** any non-2xx response or network error → red toast in the top-left
  for 4 seconds with the server's `detail` (or `Network error`). No `alert()`.
- **Export:** `Export` is a plain link to `GET /markers/export`; the server's
  `Content-Disposition` header makes the browser save `markers.json`:
  `{"markers": [{id, lng, lat, score}, ...]}`.
- **One request per marker at a time:** while a `PUT`/`DELETE` for a marker is in
  flight the marker is locked (half-transparent, not draggable, click ignored), so
  two requests for the same marker can never overlap.
- **Import:** button `Import` opens a file picker (`.json`). File must have the
  export shape; `id` is ignored. Sent to `POST /markers/import`; on success the
  new markers are added to the map. Invalid file → toast, nothing added.
  A file with zero markers → neutral toast so the user knows nothing was there.
- **Clear:** button `Clear all` → `DELETE /markers` → map emptied.

## Acceptance checklist

- [ ] Map renders with the token from `VITE_MAPBOX_TOKEN` (token is not committed).
- [ ] Click → score popup → marker appears with the right color.
- [ ] Roughly every 3rd creation shows the error toast and no marker appears.
- [ ] Score change recolors the marker and updates the panel.
- [ ] Drag moves the marker; reload keeps the new position (server state).
- [ ] Remove deletes the marker and updates the panel.
- [ ] Panel shows Total + Five..Zero and is correct after each operation.
- [ ] Export downloads a valid `markers.json`.
- [ ] Import of an exported file adds the markers; broken JSON → toast only.
- [ ] Server stopped → any action shows a toast, UI stays consistent.
- [ ] `pytest` green; `docker compose up` runs client + server.
